# 移動カメラ（実験モード）

同じレンズ、ズームなし、カット切替なしを前提に、GeoCalibの歪み補正とDepth Anything 3のカメラ推定を組み合わせます。従来の固定カメラBATはそのまま使えます。

## Windowsセットアップ

1. NVIDIA GPUと対応ドライバを用意し、`SetupMovie2Anim.bat` を実行する。
2. `DropVideoToMovie2Anim.bat` に動画をドロップする。

初回はネット接続、Git、起動用Pythonが必要です。PythonはPATHの `python`、または `M2A_PYTHON` で指定します。カメラ専用のPython 3.12はuvが自動調達します。通常推論はローカルの重みを読み、UEやネット接続を必要としません。

既存の `.venv`（Python 3.13 / ONNX Runtime DirectML）にTorchは入れません。`.venv-camera`（Python 3.12 / NumPy 1.26.4 / torch 2.7.1+cu128 / torchvision 0.22.1+cu128）を作り、別プロセスで実行します。GPU処理が終わってプロセスが終了してから人体推定へ進むので、DA3とHueは同時にVRAMを占有しません。

RTX 5090（Blackwell）対応のためCUDA 12.8版の公式Windows wheelを使います。参考にしたImage_to_Meshのtorch 2.6/cu126は採用していません。推論にCUDA Toolkitやnvccのインストールは不要です。PyTorchのCUDA演算を実行してセットアップを検証します。gsplat、xformers、Open3D、Gradioはこのカメラ推論経路には不要で、公式ソースのTorch SDPAを使います。DA3のパッケージ宣言全体を入れず、必要な推論依存を `requirements-camera.txt` で管理するため、pip checkには未使用の追加依存が表示される場合があります。

## 処理と出力

1. 最大5枚の画像を用いて共通の焦点距離とsimple-radial歪み係数を推定。全フレームを同じ中央主点・正方画素のピンホール映像に補正する。
2. 補正済み映像で人物追跡し、追跡人物と信頼度0.45以上の検出人物の領域を背景検証から除く。DA3ネットワーク自体は元の補正映像を見ている。
3. 24フレーム窓・8フレーム重複、長辺最大336pxでDA3を実行。各窓の全フレームに姿勢を出す。単一画像を独立処理する方法や、間引きカメラの単純補間ではない。
4. DA3の深度とカメラ姿勢を初期情報にして、固定内部行列の背景PnPでカメラを順次推定する。前フレームの補正姿勢を引き継ぐDA3深度ベースのVisual Odometry（VO）であり、DA3が出した絶対姿勢の単純な後処理ではない。重複フレームの背景深度から共通尺度を求め、最後の共通カメラ姿勢を厳密に合わせたSim(3)変換で窓をつなぐ。背景不足、低いinlier率、不整合な接続で区間を分割し、後続を再探索する。
5. 全人物の胴体深度とHueの深度から一つの尺度を推定し、カメラの逆変換で世界座標へ変換。重力・初期接地を合わせてQuinnへリターゲットする。

`runs/drop/<ID>/camera/` に次を保存します。

- `lens.json`：元・補正後の内部行列、歪み係数、校正サンプル。
- `rectified.avi`：全フレームのFFV1補正映像。音声なし。
- `trajectory.npz`：OpenCVのworld-to-camera行列、内部行列、フレーム番号、重力方向。
- `depth/*.npz`：各フレームの低解像度深度・信頼度。
- `window_*.npz`：DA3の生のカメラ姿勢と補正姿勢。
- `camera_report.json`：背景再投影誤差、inlier数、窓の接続誤差。
- `body_alignment.json`：共通尺度とばらつき、人体との統合方式。
- `camera_preview.html`：人体尺度・床合わせ前のカメラ位置。

FBX名・保存先・上書き禁止は通常BATと共通です。失敗時も実行ディレクトリに中間結果を残します。

## 精度の範囲

これは移動カメラの実験的な統合です。Hueの未公開CamAngvel表現を推測して投入せず、従来と同じゼロ入力で得た出力をカメラ相対と見なして世界変換しています。動くカメラによる人体モデル内部の誤推定までは取り除けません。人体深度と表面深度にはずれがあるので、絶対距離は推定値です。DA3/PnPの深度補正は近似で、人体・カメラの同時最適化は未実装です。

背景の再投影誤差は内部整合性の検査で、カメラ軌跡の真値に対する精度保証ではありません。高速なブレ、背景の少ない映像、多数の通行人、長い遮蔽、カット切替は失敗し得ます。窓接続はドリフトを蓄積する可能性があり、ループ閉合は行いません。初期両足接地は従来どおり仮定します。最初から歩行中なら `--no-tilt-correction` を指定できます。

検証記録と進捗は `MOVING_CAMERA_PLAN.md` を参照してください。


移動モードで冒頭に大きな人物が見つからない場合のみ、人物の最小高さを画面高さの18%から6%へ下げます。遠くから近づく人物への対応です。低信頼区間や長い不在を無条件に補間する処理ではありません。

## 現行仕様：全動画から成功した全区間を出力

最初の失敗で終了する先頭区間のみの方式を廃止しました。カメラ接続が失敗したら、保存済み区間を確定し、次の未採用フレームから独立したカメラ座標で再開します。独立窓でも背景幾何検証に失敗する場合は12フレーム窓へ縮め、1フレームずつ開始位置を進めて、後半の有効区間を探します。判定閾値は緩めません。

- 検証を通った連続区間をすべて別FBXへ出力。区間間は別の座標原点・推定尺度であり、空間的に連結しません。
- 各区間の最初でGeoCalibの重力を再推定します。レンズ補正と焦点距離は動画全体で固定した値を維持します。
- 全人物を同じ元動画フレーム範囲で推定します。ある区間の人体推定・尺度合わせ・出力が失敗しても、理由を記録して後の区間を処理します。
- 出力名は `動画名_frames_000072-000319_segment.fbx`。番号は0始まり・両端を含み、FBX時間は0から始まります。同名JSONに区間情報と精度警告を保存します。
- `動画名_segments.json` に全成功区間、カメラの除外範囲・失敗理由、人体段階の失敗を記録します。JSONのstart/endは半開区間 `[start,end)` です。
- 全長が一つの区間として完了した場合は従来の `動画名.fbx`。既存ファイルは上書きしません。
- 単独区間は人体モデルの制約で最低12フレーム必要です。接続できない短い末尾などは理由を付けて除外します。
- 判定通過は内部整合性の検証であり、人体姿勢やカメラの真値に対する精度保証ではありません。quality_warningsは区間ごとに残します。

## 配布用BATと保存場所

`SetupMovie2Anim.bat` は人体セットアップの後にカメラセットアップを順次実行します。UEフォルダ選択、人体用venv、UEモデル取得・既存モデルのハッシュ確認、FBXツールのビルド、検出モデル、カメラ用venv、CUDA Torch、GeoCalibとDA3-LARGEまでが対象です。初期条件と引数はREADMEを参照してください。既存モデル・実行結果は削除しません。GPUモデルを含む一括セットアップの再実行を確認済みです（work/setup_all_validation.log）。新規PCそのものでは未検証です。

`DropVideoToMovie2Anim.bat` に動画をドロップすると、元動画の隣に `動画名_Movie2Anim_日時_ID/` を新規作成します。全成功区間のFBXとJSON・区間一覧を直下、カメラ・人体の中間結果とプレビュー・エラー詳細を `_work/` に保存します。繰り返し実行しても別フォルダになります。複数動画は動画ごとに保存します。初期接地を仮定しない場合は `--no-tilt-correction` を追加できます。

再ドロップの保存先分離とセットアップの引数・異常終了を含む33テスト成功（work/packaging_tests.log）。

カメラ用Python本体は runtime-camera/python/ に配置します。既存venvがユーザー配下のuv管理Pythonを参照している場合は、一括セットアップ時に同じバージョンの本体をプロジェクト内へコピーし、pyvenv.cfgをバックアップして参照先を切り替えます。モデルとインストール済みパッケージは保持します。2026-09-07に既存環境の参照を修復し、CUDAとカメラライブラリの起動を確認しました。


## 人物追跡の区間対応（2026-09-07）

移動カメラモードは人物が全長で見えていることを要求しません。追跡IDごとに短い欠測のみ補間し、長い不在で分割します。登場前・退場後へ矩形を延長しません。候補区間は最低12フレーム・6観測が必要です。追跡可能な人物集合が変わる位置で区間を切り、カメラの有効区間との共通部分をすべて処理します。同時に3人以上の追跡IDがある範囲と、12フレーム未満の独立区間は除外理由を記録します。動画全体で3つ以上のIDがあっても、各区間が1〜2人なら処理対象です。

区間ごとのscene.jsonのtrackingに元の追跡IDを記録し、segments_manifest.json / 動画名_segments.jsonのtracking_skipped_rangesへ除外範囲を記録します。カメラの切り出しは対応する深度フレームも同じ範囲へ揃えます。固定カメラ用BATの全長追跡条件は従来どおりです。

途中登場・長い不在・3人同時と順次登場・深度とカメラのフレーム対応を含む36テスト成功。二人の実動画16フレームも両者を同じ範囲で出力し、個別89ボーン・結合179ボーンのFBX再読込行列誤差0を確認（runs/tracking_intervals_pair01）。報告された1337フレーム動画そのものの再実行結果ではありません。
